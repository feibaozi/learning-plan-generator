前置知识背景与缘起⏱ 约3分钟

从统计语言模型到Transformer再到GPT系列，大语言模型的发展路径清晰可见。了解这段历史，能帮你理解为什么LLM是现在这个样子。

语言模型的演进：

  • 早期（1990s-2010s）： n-gram模型、统计语言模型 —— 基于频率统计预测下一个词
  • 深度学习时代（2013-2017）： Word2Vec、RNN、LSTM —— 首次用神经网络学习词向量和序列依赖
  • 革命（2017）： Transformer架构发表 —— 自注意力机制突破序列长度限制
  • GPT时代（2018-至今）： GPT-1→GPT-2→GPT-3→GPT-4 —— 规模与能力的指数级增长
年份里程碑关键创新能力等级
2017Transformer论文自注意力机制基础架构
2018GPT-1生成式预训练文本补全
2019GPT-2无监督多任务故事生成
2020GPT-3规模突破(175B)少样本学习
2022ChatGPTRLHF对齐对话能力
2023GPT-4多模态+高级推理专家级任务

为什么这些对提示工程师重要？知道模型如何学习、如何生成，你就能理解：

  • 为什么提示的顺序很重要（自回归生成）
  • 为什么模型会"幻觉"（训练数据与生成目标的差异）
  • 为什么角色扮演有效（系统提示改变上下文分布）
  • 为什么思维链提示能提升推理（逐步生成激活正确的注意力模式）

核心概念核心概念⏱ 约4分钟

LLM的核心机制是一个三层结构：Transformer架构处理输入，自回归模式逐词生成，训练管线决定了模型知道什么和如何响应。
图：LLM核心机制三层结构

第一层：Transformer架构

Transformer是LLM的"大脑"，由多个相同的层堆叠而成。每个层包含两个核心组件：

  • 自注意力机制：让模型能"看到"输入中所有位置的信息，并根据相关性加权
  • 前馈神经网络：对每个位置的信息进行独立处理和变换

第二层：自回归生成

LLM生成文本的方式是逐token预测：

  • 每次只生成一个token
  • 生成下一个token时，基于前面所有已生成的内容
  • 从概率分布中采样选择下一个token
自回归生成概率公式 $$P(w_1, w_2, ..., w_n) = \prod_{i=1}^{n} P(w_i | w_1, w_2, ..., w_{i-1})$$
这个公式表示：生成整句文本的概率等于逐词生成概率的乘积。每个词的生成概率都依赖于前面已经生成的所有词。这就是为什么提示中前面的内容会对后面的生成产生巨大影响——每一步都在条件化后续的生成分布。

第三层：训练管线

现代LLM的训练通常包含三个阶段：

  1. 预训练：在海量文本上学习预测下一个token
  2. 指令微调：用指令-响应对教模型遵循人类指令
  3. RLHF：用人类反馈强化学习对齐人类偏好
💡 核心洞察：理解这三层结构，你就掌握了LLM的90%。提示工程本质上是在第二层（自回归生成）中通过精心设计的输入条件，引导模型从第一层（Transformer）中激活正确的知识，而第三层（训练）则决定了模型有哪些知识可以被激活。

核心原理核心原理：三层结构⏱ 约5分钟

现在让我们深入这三层结构的工作原理，以及它们如何共同作用产生你看到的输出。

一、Transformer：理解上下文的引擎

1输入嵌入：将文本token转换为高维向量
每个token对应一个d维向量（如GPT-3是12288维）
2位置编码：给向量添加位置信息
Transformer不知道顺序，需要显式编码位置
3自注意力层：计算每个位置对其他位置的关注度
多头注意力让模型同时关注不同类型的关系
4前馈层：对每个位置独立进行非线性变换
这是模型"思考"和应用知识的地方

二、自回归生成：逐词构建的艺术

想象你在玩"词语接龙"游戏，每次只能说一个词，但必须让整句话连贯——这就是LLM在做的事。关键区别是：

  • LLM知道所有可能的"下一个词"的概率
  • 它不是随便选一个，而是根据参数（temperature、top-p等）从分布中采样
  • 选好一个词后，把它加到上下文里，再猜下一个
自回归生成的简化伪代码 def generate(prompt, max_new_tokens=50): tokens = tokenize(prompt) for _ in range(max_new_tokens): # 预测下一个token的概率分布 logits = model(tokens) # 根据temperature等参数采样 next_token = sample(logits, temperature=0.7) # 添加到序列中 tokens = tokens + [next_token] # 如果是结束符就停止 if next_token == EOS_TOKEN: break return detokenize(tokens)

三、训练管线：三个阶段的旅程

阶段目标数据对提示工程的影响
预训练学习世界知识万亿token的互联网文本模型知道什么事实、语言模式
指令微调学会遵循指令百万级指令-响应对模型理解"请帮我..."这类请求
RLHF对齐人类偏好人类偏好标注模型输出更有帮助、更安全

核心原理Transformer架构⏱ 约5分钟

自注意力机制是Transformer的核心。理解它如何工作，你就能明白为什么提示中的某些部分比其他部分更有影响力。
图：Transformer编码器-解码器架构（简化版）

自注意力机制详解：

自注意力计算三个向量：Query（查询）、Key（键）、Value（值）

缩放点积注意力公式 $$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$
直观理解：Q是"我在找什么"，K是"这里有什么"，V是"这里的内容是什么"。计算Q和所有K的相似度，用softmax归一化得到权重，然后用权重对V加权求和。$\sqrt{d_k}$是缩放因子，防止点积值过大导致softmax饱和。

多头注意力：

Transformer不是只用一组注意力，而是用多组（"头"），每组学习不同类型的关系：

  • 有的头关注语法关系（主谓一致）
  • 有的头关注指代关系（"它"指什么）
  • 有的头关注语义相似性

对提示工程的启示：

💡关键信息放前面或后面
注意力机制有"近期偏见"和"开头偏见"，重要提示放在这两个位置效果更好
💡用分隔符区分不同部分
用---或###等分隔符帮助模型正确分段注意力
💡重复重要指令
在提示开头和结尾各说一次，增加被注意到的概率

核心原理自回归生成⏱ 约5分钟

自回归生成是LLM最基本的行为模式。理解这个过程，你就能解释很多看似神秘的模型行为。
图：自回归生成过程可视化

生成的每一步都在做什么？

  1. 输入当前所有token到Transformer
  2. Transformer输出下一个位置每个可能token的logits
  3. 对logits应用softmax得到概率分布
  4. 根据采样策略（temperature、top-p等）选择一个token
  5. 将这个token加到输入序列末尾
  6. 重复直到生成结束符或达到最大长度

三个有趣的观察及其提示工程应用：

观察解释提示技巧
模型很难"反悔"一旦生成了某个内容，后续生成都会基于它生成前让模型"先思考再回答"，把推理过程写在前面
输出的开头至关重要前几个token定下了整个生成的基调在提示中给出理想输出的前几个词或模板
模型会"补全"模式它在训练中见过太多文本模式，会自动延续用few-shot示例建立你想要的模式
💡 思维链为什么有效？ 因为当模型逐token生成推理步骤时，每一步的推理都会改变后续的注意力分布，引导模型激活正确的知识路径。这就像你在做数学题时把中间步骤写下来——写的过程帮助你思考。

核心原理训练管线⏱ 约5分钟

训练决定了模型的"本性"。知道模型是怎么训练出来的，你就能理解它的优势和局限性。

第一阶段：预训练 —— 学习预测下一个token

预训练是LLM学习的主要阶段，目标很简单：给定前文，预测下一个token。

预训练目标函数 $$\mathcal{L} = -\sum_{t=1}^{T} \log P(w_t | w_1, ..., w_{t-1}; \theta)$$
这是负对数似然损失。模型要最大化正确下一个token的对数概率，等价于最小化这个损失。关键洞察：模型学的不是"真相"，而是"文本中什么最可能接着出现"。这解释了为什么模型会产生幻觉——有些内容虽然不真实，但在训练数据的模式下很"合理"。

第二阶段：指令微调 —— 学会"听从指令"

预训练模型是个"补全机器"，但不知道如何响应用户请求。指令微调就是用大量（指令，响应）对来教它：

  • "把这封信翻译成法语" → 法语翻译
  • "总结这篇文章" → 摘要
  • "帮我写一个Python函数" → 代码

第三阶段：RLHF —— 对齐人类偏好

即使经过指令微调，模型的输出也不一定符合人类偏好。RLHF通过三个步骤解决这个问题：

  1. 收集人类对模型输出的偏好排序
  2. 训练一个奖励模型预测人类偏好
  3. 用强化学习训练LLM最大化奖励
图：RLHF三阶段流程

对提示工程的关键启示：

1模型会模仿训练数据中的模式
如果你的提示像论文，它的输出也会像论文
2系统提示特别有效
因为指令微调阶段看到了大量系统-用户-助理的对话格式
3模型倾向于"有帮助"但不一定"准确"
这是RLHF优化的结果——"承认不知道"可能得分更低

实践应用实践案例⏱ 约4分钟

让我们用这些原理来分析几个经典提示技巧为什么有效——知其然，更知其所以然。

案例一：为什么思维链提示有效？

普通提示 vs 思维链提示 # 普通提示 用户：一个球从10米高处落下，每次反弹高度是前一次的一半，第3次落地时共经过多少米？ 模型：10 + 5 + 2.5 + 1.25 = 18.75米（错误） # 思维链提示 用户：一个球从10米高处落下，每次反弹高度是前一次的一半，第3次落地时共经过多少米？让我们一步步思考。 模型： 1. 第一次落下：10米 2. 第一次反弹：5米上去，5米下来 = 10米 3. 第二次反弹：2.5米上去，2.5米下来 = 5米 4. 第三次落地：到达地面停止 总计：10 + 10 + 5 = 25米（正确）

原理分析：

  • 自回归生成让模型"先想再做"——每一步推理都改变后续的注意力分布
  • Transformer的注意力机制在逐步推理中能更好地追踪中间结果
  • 训练数据中有很多"推理→结论"的模式，模型学会了延续这种模式

案例二：为什么角色扮演（系统提示）有效？

系统提示的魔力 # 无系统提示 用户：解释量子纠缠 模型：量子纠缠是一种量子力学现象...（学术解释） # 系统提示 系统：你是一位给5岁孩子解释科学的老师，用简单的语言和比喻。 用户：解释量子纠缠 模型：想象你有两个魔法箱子...

原理分析：

  • 系统提示放在对话开头，利用了Transformer的"开头偏见"
  • 它设定了整个生成的上下文分布——模型在训练中见过很多"角色→响应"的模式
  • RLHF让模型特别重视系统级的指令
💡 从原理到实践： 每个有效的提示技巧背后都有LLM工作原理的支撑。当你理解了这些原理，你就不再是死记硬背技巧，而是能根据原理创造新技巧。
