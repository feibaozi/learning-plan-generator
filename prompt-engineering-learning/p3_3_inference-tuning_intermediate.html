前置知识背景与缘起⏱ 约3分钟

为什么需要这些参数？因为 LLM 输出的是概率分布——我们需要从这个分布中选择 token，不同的选择策略会产生完全不同的结果。

推理过程的本质：

在每一个时间步，模型会为词表中的每一个 token 计算一个概率（logits → softmax → 概率）。然后我们需要：

  1. 从这个概率分布中选择下一个 token
  2. 将选中的 token 添加到输入序列末尾
  3. 重复直到生成结束
图：从概率分布到token选择

采样策略的演进：

策略描述特点
Greedy (贪婪)总是选择概率最高的 token确定但容易重复
Random (随机)从分布中完全随机采样创意但不一致
Temperature调整分布的"平坦度"控制随机性的简单方法
Top-k只从概率最高的 k 个 token 中选择限制选择范围
Top-p (Nucleus)从累积概率达到 p 的最小集合中选择动态适应分布
💡 核心洞察： 这些参数不是孤立的——它们共同作用来控制"模型应该有多确定地选择最可能的 token"。

核心参数🌡️ Temperature 参数⏱ 约6分钟

Temperature 是最常用的参数——它控制概率分布的"温度"，也就是分布的平坦程度。

工作原理：

Temperature 缩放公式 $$ P'(token_i) = \text{softmax}\left(\frac{\text{logits}_i}{T}\right) $$
当 T→0 时，softmax 会变得越来越尖锐，最终相当于 argmax（贪婪选择）。当 T→∞ 时，分布会变得越来越平坦，趋近于均匀分布。T=1 时保持原始分布不变。
图：不同 Temperature 下的概率分布

Temperature 效果参考：

值效果适用场景
0.0 - 0.3非常保守、确定，重复率高代码生成、事实问答、数学计算
0.3 - 0.7平衡，有一定随机性但稳定日常对话、总结、解释
0.7 - 1.2创意，多样性好写作、头脑风暴、创意生成
1.2 - 2.0非常随机，可能不连贯实验性创作、寻找意外发现
Temperature 效果对比示例 # 同一个提示，不同 temperature prompt = "给咖啡店起一个名字：" # Temperature=0.0 → 输出总是相同的 output: " Brew & Bean" # Temperature=0.7 → 每次略有不同但合理 output: "Steam & Stories" output: "Café Crescendo" # Temperature=1.5 → 变化很大，可能奇怪 output: "Zap-Zap Coffee Cloud" output: "Cosmic Croissant & Quasar"
💡 提示工程师经验： 大多数场景下 0.7 是不错的起点。对于需要精确性的任务，0.2-0.3 更好；对于创意写作，0.8-1.0 合适。

核心参数🎯 Top-p (Nucleus) 采样⏱ 约6分钟

Top-p 是一个更智能的截断策略——它不固定选择数量，而是选择累积概率达到 p 的最小 token 集合。

工作原理：

  1. 将 token 按概率从高到低排序
  2. 从最高概率开始累加，直到累积概率 ≥ p
  3. 只从这个最小的 token 集合中采样
图：Top-p=0.9 时的 Nucleus 采样

Top-p 效果参考：

p 值效果适用场景
0.5 - 0.7非常严格，只选最可能的几个精确任务、代码生成
0.8 - 0.9平衡，多样性和质量兼顾一般对话、写作
0.9 - 1.0宽松，考虑更多可能创意写作、多样化生成
💡为什么 Top-p 通常比 Top-k 好？
因为概率分布的形状是变化的——有时概率集中在少数几个 token，有时分布很平坦。Top-p 能自适应调整，而 Top-k 总是固定数量。

Temperature + Top-p 组合使用：

这两个参数通常一起使用：先用 temperature 调整分布的形状，再用 top-p 截断。大多数 API 会先应用 temperature，再应用 top-p/top-k。

💡 黄金组合： temperature=0.7 + top-p=0.9 是很多场景下的安全起始点。

核心参数🔢 Top-k 采样⏱ 约4分钟

Top-k 是一个更简单的策略——只从概率最高的 k 个 token 中选择。

工作原理：

  1. 选择概率最高的 k 个 token
  2. 将其他 token 的概率置为 0
  3. 重新归一化剩余概率
  4. 从中采样

Top-k 效果参考：

k 值效果适用场景
1贪婪选择（总是选最可能的）需要绝对确定性
10 - 30有限选择范围平衡质量和多样性
50 - 100较大选择范围创意写作
≥ 词表大小不截断（等效于不设置）不推荐使用
⚠️Top-k 的问题
固定 k 可能不合适——当分布很平坦时，k=50 可能不够；当分布很集中时，k=50 又可能包括一些低概率的奇怪 token。

何时使用 Top-k 而非 Top-p：

  • 需要严格限制选择范围时
  • 某些特定模型的推荐配置
  • 需要可预测的计算成本时

核心参数⚖️ 频率与存在惩罚⏱ 约5分钟

这两个参数用于减少重复——它们通过降低已出现 token 的概率来鼓励多样性。

Frequency Penalty（频率惩罚）：

根据 token 在文本中已出现的次数来惩罚——出现次数越多，惩罚越大。

频率惩罚公式 $$ \text{logits}_i' = \text{logits}_i - \text{frequency_penalty} \times \text{count}_i $$

Presence Penalty（存在惩罚）：

只要 token 出现过就惩罚一次——不管出现多少次。

存在惩罚公式 $$ \text{logits}_i' = \text{logits}_i - \text{presence_penalty} \times (1 \text{ if } \text{count}_i > 0 \text{ else } 0) $$
参数范围效果适用场景
frequency_penalty-2.0 到 2.0惩罚频繁出现的词列表生成、多样化内容
presence_penalty-2.0 到 2.0鼓励使用新词头脑风暴、创意写作
惩罚参数效果示例 # 没有惩罚时可能会重复 output: "咖啡很好喝，咖啡很香，咖啡很提神..." # frequency_penalty=1.0 时 output: "咖啡很好喝，香气浓郁，提神醒脑..." # presence_penalty=1.0 时 output: "咖啡很好喝，拿铁很香，浓缩咖啡提神..."
💡 使用建议： 0.1-0.3 是温和的惩罚，适合大多数场景。不要使用过高的值（>1.0），否则输出会变得不自然甚至胡言乱语。

核心参数📏 Max Tokens 与长度控制⏱ 约4分钟

控制输出长度——虽然简单，但这是避免过长或过短输出的关键参数。

常用的长度参数：

参数描述注意事项
max_tokens / max_new_tokens最大生成 token 数记住输入 + 输出 ≤ 模型上下文窗口
min_tokens最小生成 token 数强制模型至少生成一定长度
stop / stop_sequences停止序列遇到这些 token 时停止生成
logit_bias调整特定 token 的 logits可以强制或禁止某些词

使用 stop 序列的技巧：

使用 stop 序列控制输出格式 # 生成 JSON 时，遇到 "}" 就停止 stop=[ "}" ] # 生成列表时，遇到空行就停止 stop=[ "\n\n" ] # 多轮对话时，遇到 "用户：" 就停止 stop=[ "用户：", "Human:", "###" ]

logit_bias 的妙用：

使用 logit_bias 控制特定 token # 完全禁止某些词（设为 -100） logit_bias={ tokenize("抱歉"): -100, tokenize("对不起"): -100 } # 强烈鼓励某些词（设为 10-100） logit_bias={ tokenize("JavaScript"): 20, tokenize("Python"): 20 }

参数调优的迭代方法：

1从推荐配置开始
使用上面表格中对应场景的配置作为起点
2微调 temperature
如果输出太随机，降低 temperature；如果太重复，提高 temperature
3调整惩罚参数
如果仍有重复，增加 frequency_penalty 和/或 presence_penalty
4用 stop 序列精确控制
如果输出格式需要严格控制，使用 stop 参数
💡 迭代法则： 一次只调整一个参数！这样你能清楚地知道每个参数的效果。

实践应用🛠️ 实用工具与示例⏱ 约5分钟

这里有一些代码示例，展示如何在常见平台上设置这些参数。
OpenAI API 参数配置示例 import openai response = openai.chat.completions.create( model="gpt-4", messages=[ {"role": "system", "content": "你是一个创意写作助手"}, {"role": "user", "content": "写一个关于咖啡的短故事"} ], temperature=0.9, # 高创意 top_p=0.95, # 宽松的 nucleus 采样 max_tokens=500, # 最多 500 token frequency_penalty=0.4, # 减少重复 presence_penalty=0.3, # 鼓励新词 stop=["###"] # 遇到 ### 就停止 )
Anthropic Claude 参数配置示例 import anthropic client = anthropic.Anthropic() response = client.messages.create( model="claude-3-opus-20240229", max_tokens=500, temperature=0.7, top_p=0.9, system="你是一个专业的代码助手", messages=[{"role": "user", "content": "写一个快速排序函数"}] )
HuggingFace Transformers 参数配置示例 from transformers import AutoTokenizer, AutoModelForCausalLM tokenizer = AutoTokenizer.from_pretrained("gpt2") model = AutoModelForCausalLM.from_pretrained("gpt2") inputs = tokenizer("给咖啡店起名字：", return_tensors="pt") outputs = model.generate( **inputs, max_new_tokens=50, temperature=0.8, top_p=0.9, do_sample=True, # 采样，不是贪婪 repetition_penalty=1.2, # 类似 frequency penalty num_return_sequences=3 # 一次生成 3 个结果 )
💡 测试工具： 大多数模型的 Playground（如 OpenAI Playground、Claude Console）都有可视化的参数调整界面——这是快速实验的最佳方式！
