## 项目驱动学习法

作为教程实操型（G8）学习方案，本方案高度强调 **项目驱动学习**。与其死记硬背概念，不如通过完成实际项目来内化知识。

### 如何通过项目学习提示工程

1. **每个阶段关联一个核心项目** — 学完技法立即实践
2. **迭代优于完美** — 第一版提示不需要完美，通过迭代不断改进
3. **建立提示库** — 将成功案例保存为可复用的模板
4. **对比实验** — 对同一个任务尝试多种提示策略并比较效果
5. **记录失败案例** — 失败的提示同样有学习价值，分析为什么失败

### 推荐工具栈

| 层 | 工具 | 用途 |
|----|------|------|
| 模型 | OpenAI API / Claude API / 本地 Ollama | 核心模型调用 |
| 编排 | Python + LangChain | 复杂提示工作流 |
| 实验 | Jupyter Notebook | 提示实验与对比 |
| 评估 | 自建评测脚本 / Promptfoo | 提示效果量化 |
| 版本管理 | Git + 提示模板文件 | 提示版本控制 |

## 第一阶段：核心工具 — 提示工程核心技法（第1-4周，共4周）

📌 **阶段目标**：掌握提示工程五大核心技法，能够针对不同任务类型选择合适的提示策略并编写高质量提示。

🔑 **核心知识点**：

- **[Zero-shot]** 零样本提示与少样本提示：无需示例 vs 通过示例引导——两种最基础的提示范式
- **[CoT]** 思维链提示：让模型"展示思考过程"，显著提升推理类任务表现
- **[Role]** 角色扮演与系统提示：通过角色设定和系统级指令精确控制模型行为

📊 **关键图示**：

```
Zero-shot 提示
┌─────────────────────────────────┐
│  任务描述 → LLM → 直接输出      │
│  无需示例，依赖模型预训练知识    │
└─────────────────────────────────┘

Few-shot 提示
┌─────────────────────────────────┐
│  示例1(输入→输出)               │
│  示例2(输入→输出)  → LLM → 输出 │
│  实际任务(输入)                  │
└─────────────────────────────────┘

Chain-of-Thought (CoT) 提示
┌─────────────────────────────────┐
│  问题: Q                         │
│  让我们一步步思考...             │
│  Step 1: ... → LLM → 推理链+答案 │
│  Step 2: ...                     │
│  答案: A                         │
└─────────────────────────────────┘
```

💻 **代码示例**：

```python
# Zero-shot 提示
response = client.chat.completions.create(
    model="gpt-4",
    messages=[
        {"role": "user", "content": "将以下文本分类为正面/负面/中性：'这个产品超出预期！'"}
    ]
)

# Few-shot 提示
response = client.chat.completions.create(
    model="gpt-4",
    messages=[
        {"role": "user", "content": """
        示例1: '太棒了' → 正面
        示例2: '很失望' → 负面
        示例3: '还行吧' → 中性
        
        请分类: '超出预期！' →"""}
    ]
)

# Chain-of-Thought 提示
response = client.chat.completions.create(
    model="gpt-4",
    messages=[
        {"role": "user", "content": """
        问题: 一个农场有15只鸡和8只兔子，共有多少条腿？
        让我们一步步思考：
        1. 鸡的腿数：
        2. 兔子的腿数：
        3. 总腿数："""}
    ]
)
```

## 第二阶段：整合应用 — 实战项目与场景应用（第5-9周，共5周）

📌 **阶段目标**：将核心技法应用于复杂实际场景，掌握提示迭代优化、多步推理分解和长文本处理等进阶能力。

🔑 **核心知识点**：

- **[Structured Output]** 结构化输出控制：通过提示精确约束模型的输出格式（JSON、表格、代码等）
- **[Iteration]** 提示迭代优化策略：从初版到精品的系统化打磨方法论
- **[Decomposition]** 多步推理与任务分解：将复杂任务拆解为模型可处理的子任务链
- **[Context]** 上下文窗口与长文本处理：充分利用模型上下文窗口的策略与技巧

📊 **关键图示**：

```
提示迭代优化循环
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 编写初版  │ → │ 运行测试  │ → │ 分析输出  │
│ 提示模板  │    │ 收集结果  │    │ 识别问题  │
└──────────┘    └──────────┘    └──────────┘
                                      ↓
┌──────────┐    ┌──────────┐    ┌──────────┐
│ 最终版本  │ ← │ 验证改进  │ ← │ 调整提示  │
│ 上线使用  │    │ A/B对比   │    │ 添加约束  │
└──────────┘    └──────────┘    └──────────┘

多步推理分解示意
复杂任务: "分析这份财报并给出投资建议"
    ├─ Step 1: 提取关键财务指标
    ├─ Step 2: 同比/环比分析
    ├─ Step 3: 行业对标分析
    └─ Step 4: 综合投资建议
```

💻 **代码示例**：

```python
# 结构化JSON输出
prompt = """
分析以下客户评论，输出严格的JSON格式：
{
  "sentiment": "positive/negative/neutral",
  "key_topics": ["topic1", "topic2"],
  "urgency": "high/medium/low"
}

评论: '快递太慢了，包装也破了，但产品质量还不错。'
"""

# 多步推理分解
def analyze_review(text):
    # Step 1: 情感分析
    sentiment = llm(f"分析情感: {text}")
    # Step 2: 要点提取
    topics = llm(f"提取关键话题: {text}")
    # Step 3: 综合判断
    conclusion = llm(f"基于以下信息给出建议\n情感:{sentiment}\n话题:{topics}")
    return conclusion
```

## 第三阶段：基础奠基 — 语言模型原理基础（第10-12周，共3周）

📌 **阶段目标**：回过头来补足 LLM 底层原理知识，理解 Tokenization、推理参数等机制，让提示设计有据可依。

🔑 **核心知识点**：

- **[LLM Basics]** LLM工作原理概述：自回归生成、Transformer 架构、预训练与对齐
- **[Tokenization]** Token化与分词原理：BPE/WordPiece、token 边界对提示效果的影响
- **[Inference]** 模型参数与推理机制：temperature、top_p、top_k 等采样参数的作用原理

📊 **关键图示**：

```
LLM 自回归生成流程
┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
│Token1 │ → │Token2 │ → │Token3 │ → │Token4 │ → ...
│ "今天" │   │ "天气" │   │ "真"   │   │ "好"   │
└──────┘   └──────┘   └──────┘   └──────┘
   ↑           ↑           ↑           ↑
   └───────────┴───────────┴───────────┘
          每步基于历史所有 token 预测下一个

采样参数效果对比
temperature=0.0  → "今天天气真好"  (确定性，每次相同)
temperature=0.7  → "今天天气真不错" (适度随机)
temperature=1.5  → "今天气候异常美妙" (高度随机/创意)
```

## 核心公式与概念速查表

| 概念名称 | 公式/定义 |
|----------|-----------|
| Temperature 采样 | `P(token_i) = softmax(logits_i / T)` — T 越小越确定，T 越大越随机 |
| Top-p 采样 | 累积概率 ≥ p 的最小 token 集合中采样 |
| 困惑度 (PPL) | `PPL = exp(-1/N * Σ log P(token_i))` — 越低表示模型越确定 |
| Token 计数估算 | 英文: ~1 token ≈ 0.75 词 \| 中文: ~1 token ≈ 1.5 汉字 |

## 实操练习题库

### 🟢 基础练习（3题）

1. **#1 零样本分类器** — 编写一个零样本提示，让模型对10条不同领域的新闻标题进行情感三分类（正面/负面/中性），准确率目标 ≥ 85%
2. **#2 少样本格式转换** — 使用3个示例引导模型将自由文本转换为固定的CSV格式输出，测试5条不同结构的输入
3. **#3 角色扮演客服** — 设计一个客服角色的系统提示，处理5个典型客户投诉场景，评估回复的专业性和一致性

### 🟡 进阶练习（4题）

4. **#4 思维链数学推理** — 使用CoT提示让模型求解一道需要多步推理的应用题，对比不使用CoT时的准确率差异
5. **#5 温度参数实验** — 对同一提示分别在 temperature=[0, 0.3, 0.7, 1.0, 1.5] 下生成5次，记录并分析输出的多样性和质量变化
6. **#6 多步推理任务分解** — 将一个"从合同文本中提取关键条款并生成摘要"的复杂任务分解为3-4个子步骤，设计完整的提示链
7. **#7 结构化输出模板** — 设计一个能稳定输出嵌套JSON结构的提示模板，测试20条不同输入，要求格式合规率100%

### 🔴 挑战练习（2题）

8. **#8 长文档提示优化** — 处理一篇5000+字的学术论文，通过分段策略和渐进式摘要提示，生成高质量的全文档摘要
9. **#9 自动评估框架** — 设计一个用LLM评估LLM输出的方案：编写评估提示，对另一个提示的输出进行多维度自动打分（准确性、完整性、格式等）

### 📦 综合项目（1题）

10. **#10 智能知识库问答系统** — 构建一个完整的基于提示工程的文档问答应用：包含文档分段、检索拼接、提示模板设计、多轮对话管理、引用溯源功能
