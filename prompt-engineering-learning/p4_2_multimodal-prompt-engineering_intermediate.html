📜 背景：从单一文本到多模态世界 背景~5 分钟

当 LLM 学会了「看」，提示工程的游戏规则被彻底改写。

2022 年之前，提示工程几乎完全是关于文本的事。GPT-3、PaLM、LLaMA 等纯语言模型的提示设计专注于 few-shot 示例、角色设定和 chain-of-thought 推理。提示工程师只需要思考一个问题：什么样的文字能引导模型产生期望的文本输出？

变化始于 2023 年 3 月 GPT-4 的发布。虽然官方技术报告仅简单提及多模态能力，但 2023 年 9 月 GPT-4V(ision) 的正式亮相标志着视觉语言模型 (VLM) 进入主流应用。几乎同期，LLaVA、MiniGPT-4 等开源项目通过视觉编码器+语言模型的桥接架构，让学术界也能参与多模态提示研究。

2024 年是爆发之年：Anthropic 发布 Claude 3 系列（全系支持视觉）、Google 推出 Gemini 1.5 Pro（百万 token 上下文+视频理解）、阿里开源 Qwen-VL、微软发布 Phi-3-Vision。多个模型在 MMMU 多学科理解基准上超越了人类平均水平。

多模态提示工程的独特挑战源于三个根本差异。第一，视觉 token 的语义密度远低于文本 token——一张 512×512 的图像可能产生 256 个 patch token，但每个 patch 只含局部像素信息，不像文字 token 承载词义。第二，空间关系理解是全新维度——用户需要指示模型关注图中的「左上角红色区域」或「第二段第三行」。第三，跨模态幻觉更加复杂——模型可能在文本推理正确但视觉定位错误，或反之。

🎯 核心概念：什么是多模态提示工程 概念~5 分钟

多模态提示 ≠ 文字提示+图片附件。它是一种全新的指令设计范式。

多模态提示工程是指为能够同时处理多种输入模态（文本、图像、视频、音频等）的模型设计、优化和评估提示指令的系统方法。其核心目标是最大化跨模态信息的利用效率，使模型在文本推理与视觉理解之间建立精确的语义桥梁。

与纯文本提示相比，多模态提示引入四个全新维度：

维度纯文本提示多模态提示
模态组合单一文本序列文本+图像+视频+音频任意组合
空间参照无（仅段落/列表结构）像素坐标、边框、区域描述、箭头标注
时序对齐文本顺序即时间顺序视频帧索引、时间戳、事件对齐
语义密度每个 token 承载固定信息量视觉 token 信息密度高度不均匀

多模态提示的典型结构可以表示为以下形式：

多模态提示的通用结构 P_multimodal = ⟨S_system, I_1, I_2, ..., I_k, T_instruction, O_format⟩
where  S_system = 系统层角色与约束设定
      I_k = 第k个视觉输入（图像/视频帧）
      T_instruction = 文本指令与问题描述
      O_format = 输出格式约束（JSON/Markdown/结构化文本）

在实际使用中，多模态提示存在几种主要格式。第一种是交错提示：Text→Image→Text→Image→Text，类似对话中穿插图片。第二种是图像先行提示：先上传所有图片，再发送文本指令。第三种是内嵌 URL/base64 提示（API 模式）：在文本中通过 URL 或 base64 编码引用图像。第四种是视频帧序列提示：将视频拆解为关键帧序列，配合时间戳文本描述。

一个关键概念是跨模态提示密度——给定总 token 预算下，文本 token 和视觉 token 的最优分配比例。研究发现，对于 VQA（视觉问答）任务，20%-35% 的 token 预算分配给视觉通常是最优的；而对于 OCR 密集任务，这一比例可达 40%-55%。

图：不同任务类型的最优模态 token 配比
🔑 多模态提示工程的核心矛盾在于：视觉信息丰富但 token 浪费大 vs 文本信息精确但承载量有限——优秀的提示设计需要在这两者之间找到任务最优平衡点。

⚙️ 工作原理：多模态模型如何「理解」提示 原理~6 分钟

从像素到语义——一条跨越视觉编码器、跨模态桥接器和语言模型的漫长流水线。

理解多模态提示工程的原理，首先要理解典型 VLM 的三段式架构。第一阶段：视觉编码，将图像通过预训练的视觉编码器（如 CLIP ViT-L/14 或 SigLIP）转化为视觉特征向量序列。第二阶段：跨模态桥接，通过可学习的投影层（如 Q-Former 或简单的 MLP 投影）将视觉特征映射到与语言模型 token embedding 相同的向量空间。第三阶段：联合推理，语言模型将视觉 token 和文本 token 拼接为一个统一的序列进行自回归解码。

图：VLM 三段式架构：视觉编码→跨模态桥接→联合推理

视觉 token 化原理：输入图像首先被划分为固定大小的 patches（如 14×14 或 16×16 像素）。每个 patch 展平后通过 ViT 编码为固定维度的向量。一张 336×336 的图像在 14×14 patch 大小下产生 (336/14)×(336/14) = 576 个 patch token，外加一个 [CLS] 分类 token，共 577 个视觉 token。这就是为什么一张图会消耗大量 token 预算——视觉信息以「铺开」的方式被编码。

视觉 token 数量计算公式 N_tokens = ⌈H / P⌉ × ⌈W / P⌉ + N_special
其中：H, W = 图像输入分辨率（像素）
      P = Vision Transformer 的 patch 大小（通常14或16）
      N_special = 特殊 token 数量（[CLS], [SEP] 等，通常1-2个）
以 GPT-4V 的分块策略为例：一张 1024×768 的图像，按 512×512 的 tile 大小切割。每个 tile 内部再按 ViT patch 编码。若 P=14，每个 tile 产生 (512/14)² ≈ 1332 个 token。GPT-4V 还需要额外的「全局缩略图」token（85 个），因此：N_total = ceil(1024/512)×ceil(768/512)×1332 + 85 = 2×2×1332+85 = 5413 tokens。这解释了为什么高分辨率图像分析的成本远高于文本对话。

跨模态注意力的核心机制：在联合推理阶段，语言模型的自注意力层中，文本 token 可以对视觉 token 进行注意力操作。这实现了文本查询与视觉键值的对齐：

跨模态注意力公式 Attention(Q_text, K_vision, V_vision) = softmax( Q_text · K_vision^T / √d_k ) · V_vision
其中：Q_text ∈ ℝ^(n_text × d_k) — 文本 token 的查询矩阵
      K_vision, V_vision ∈ ℝ^(n_vision × d_k) — 视觉 token 的键值矩阵
      d_k — 注意力头的维度

这个公式的美妙之处在于，文本 token 通过 Q 矩阵「查询」视觉 token 的 K 矩阵，选择性地关注与当前文本语义相关的图像区域。对于 prompt 设计来说，这意味着文本指令中的空间描述词（如「左上角」、「红色区域」、「第二列」）会直接影响注意力权重的分布。

视觉指令微调是多模态模型获得 prompt 遵循能力的关键阶段。与纯文本模型不同，VLM 的微调数据需要包含图像-文本-答案三元组。典型的数据集包括 LLaVA-Instruct-150K（由 GPT-4 生成的对话）、ShareGPT4V 等。微调阶段通常冻结视觉编码器，只更新投影层和部分 LLM 参数，以保留视觉表征质量的同时赋予模型指令遵循能力。

视觉指令微调损失函数 L(θ) = - Σ log P(y_t | I, T_prompt, y_{<t}; θ)
其中：I 为输入图像
      T_prompt 为文本提示
      y_t 为第 t 步的目标输出 token
      θ 为可训练参数（投影层+部分LLM层）
🔑 多模态模型的「理解」本质是一个双阶段映射过程：首先将视觉信号映射到与语言相同的向量空间，然后通过跨模态注意力让文本查询在视觉特征中「找到」相关信息。

🏗️ 系统架构：多模态提示流水线设计 架构~5 分钟

从单次 API 调用到生产级流水线——工程现实中需要考虑的不只是 model.generate()。

在生产环境中，多模态提示工程远不止给模型发送一张图和一段文字那么简单。一个完整的多模态提示流水线通常包含五个阶段：

阶段一：图像预处理。原始输入图像需要经过格式校验（JPEG/PNG/WEBP）、分辨率调整、压缩优化、方向校正（EXIF 旋转）等步骤。分辨率选择是一个重要的权衡：过高的分辨率意味着指数增长的 token 消耗，过低则丢失关键细节。推荐的策略是自适应分辨率——OCR 任务使用高分辨率（>1024px 短边），场景描述使用中分辨率（512-768px），物体检测使用低分辨率+标注框。

阶段二：视觉 token 化。预处理后的图像通过模型专属的编码流程转化为视觉 token。此处关键决策是多图策略：多张图片是独立编码还是拼接为一张大图？独立编码保留每张图的完整语义但消耗更多 token，拼接减少 token 但可能引入布局歧义。对于 GPT-4V，多张独立图片每张都需要独立的 token 分配。

阶段三：提示组装。将系统消息、视觉 token、文本指令按模型要求的格式组装。典型结构如下：

提示组装结构（GPT-4V API 风格） messages = [
  {"role": "system", "content": S_role + S_constraints},
  {"role": "user", "content": [
    {"type": "text", "text": T_instruction},
    {"type": "image_url", "image_url": {"url": I_base64, "detail": D_level}}
  ]}
]
其中 D_level ∈ {"low", "high", "auto"} 控制视觉分辨率和 token 预算

阶段四：模型推理。结合温度参数、max_tokens、stop 序列等推理配置。多模态推理的独特考虑包括：是否启用思维链来引导视觉推理（如「请先描述图像中的关键元素，再...」），以及是否使用结构化输出（JSON mode）来约束模型以固定格式返回视觉分析结果。

阶段五：输出解析与校验。多模态模型的输出解析比纯文本更具挑战性——需要验证空间坐标的有效性、检测模棱两可的描述、识别视觉幻觉。常见的后处理包括：坐标归一化、边界框合理性检查、引用区域与原文对比验证。

📈 发展历程：多模态模型能力演进 发展~5 分钟

三年时间，从「能看图说话」到「实时视频理解」——多模态的进化速度远超 LLM。

2023 年——突破之年。GPT-4V 的发布是整个领域的转折点。它不仅能在自然图片上做视觉问答，还展现出惊人的文档分析、数学公式识别和 UI 理解能力。同时，LLaVA 项目证明只需 ~150K 条 GPT-4 生成的视觉指令数据，就能让小模型获得显著的多模态对话能力，开启了开源 VLM 的繁荣时代。

2024 年——视频与长上下文。Gemini 1.5 Pro 将多模态上下文窗口推至百万 token 级别，使得整部电影级别的视频理解成为可能。Claude 3 Opus 在精细视觉推理任务上达到甚至超越 GPT-4V。Qwen2-VL 支持动态分辨率和多图像交错理解，在 MMBench 上取得开源最佳成绩。

2025-2026 年——实时融合。GPT-4o 实现了文本、视觉和音频的原生多模态融合（而非多个独立模型的拼接），端到端延迟降至 232ms（接近人类对话反应时间）。实时视频通话、屏幕共享理解、3D 场景交互等应用场景开始浮现。多模态 agent 成为新趋势——模型不仅能看，还能基于视觉信息调用工具、操作 UI。

💼 应用场景：多模态提示的实战领域 应用~5 分钟

从医疗影像到自动驾驶——多模态提示正在重塑各行各业的 AI 交互方式。

多模态提示工程的应用已经渗透到多个垂直领域。以下按照技术难度从低到高介绍六大典型场景：

场景一：文档理解与 OCR。这是目前应用最成熟的场景。典型 prompt 模式：「请提取本发票中的：{发票号, 日期, 金额, 税号}，以 JSON 格式返回」。进阶技巧包括：要求模型先「逐区域描述文档布局（layout-aware prompting）」再提取信息，以及使用多张裁剪图片分别处理表格、印章等不同区域。

场景二：UI 自动化测试。GPT-4V/Claude 能理解软件截图的 UI 结构和状态。典型 prompt：「检查此登录页面截图，验证：(1) 用户名输入框是否存在 (2) 「登录」按钮是否可见 (3) 是否有错误提示信息。对每个检查项返回 PASS/FAIL 及理由」。更高阶的用法是将 UI 截图结合无障碍树数据，实现视觉+结构化混合理解。

场景三：医疗影像辅助分析。在放射影像（X 光、CT、MRI）分析中，多模态提示表现突出。Prompt 模式：「请分析此胸部 X 光片：(1) 描述整体影像质量 (2) 标注你观察到的异常区域 (3) 给出鉴别诊断建议（不超过3个）。请注意，你应明确声明你的分析仅供参考。」关键设计要点：必须要求模型声明置信度和使用免责声明。

场景四：电商商品理解。结合商品图片和规格文字，进行属性提取、合规检查、竞品对比。典型 prompt：「对比这两张商品图片，分析：包装差异、品牌信息、成分表异同。输出对比表格。」

场景五：自动驾驶场景理解。分析行车记录仪/车载摄像头帧序列，进行场景描述和风险评估。prompt：「你是一名驾驶安全分析师。请分析这段连续 5 帧的视频截图：(1) 识别所有交通参与者 (2) 评估当前风险等级 (3) 指出潜在危险行为。」

场景六：无障碍辅助。为视障用户提供实时环境描述。prompt 设计注重时效性和安全性：「请在 3 秒内描述你看到的场景，重点关注：前方是否有障碍物、红绿灯状态、行人位置。用简洁的短句，不超过 30 个词。」

图：各应用场景的技术成熟度与商业价值矩阵
🔑 不同场景的多模态 prompt 设计差异巨大——医疗需要低置信度声明，自动驾驶需要实时约束，无障碍需要简洁输出——没有「万能 prompt 模板」。

🔬 案例研究：构建发票 OCR 分析流水线 案例~6 分钟

从一张模糊的收据照片到结构化的 JSON 数据——完整的端到端实践。

本案例展示如何用 GPT-4V 构建一个生产级发票/收据分析流水线。目标是接收手机拍摄的任意角度、任意光照条件下的收据照片，输出标准化的结构化数据。

第一轮：朴素 prompt（基线）。我们从一个最简单的 prompt 开始：

v1 朴素 prompt 「请提取这张收据中的所有信息。」

结果：模型返回了一段自由文本，混合了商品名、价格、日期，格式混乱且有几个 OCR 错误（如「1,280」被读作「1280」缺少千位分隔符校验）。准确率约 65%。

第二轮：结构化 prompt。引入明确的字段定义和输出格式约束：

v2 结构化 prompt（字段约束） 「请将此收据解析为以下 JSON 格式：
{
  "merchant": "商家名称",
  "date": "YYYY-MM-DD",
  "items": [{"name":"...","qty":N,"unit_price":N}],
  "subtotal": N,
  "tax": N,
  "total": N,
  "currency": "币种"
}
如果无法确定某字段，填写 null。」

结果：输出格式固定为 JSON，但模型在「subtotal」和「tax」字段上出现计算错误——它将收据中的预计算值与原始 item 价格之和混淆。准确率提升至 78%。

第三轮：思维链+自验证 prompt。引入模型自我验证步骤：

v3 思维链自验证 prompt 步骤1: 逐行读取收据中的每个商品条目，记录名称、数量和单价。
步骤2: 计算每个条目的金额 = 数量 × 单价。
步骤3: 汇总所有条目金额，与收据上的小计 (subtotal) 对比。
步骤4: 如果汇总值与 subtotal 不一致，标注差异并选择收据标注值。
步骤5: 按指定 JSON 格式输出最终结果。

结果：准确率提升至 93%。模型在步骤 3 中自动发现了一处价格计算不一致（收据打印错误）并正确标注。

第四轮：多图+图像预处理。针对低质量图片，增加预处理步骤：将模糊区域裁剪放大为独立图片，分两次提交给模型（先看整体布局，再看局部细节）。同时增加亮度/对比度自适应调整。

最终结果：准确率达到 96.5%。处理一张收据的端到端延迟约 3.2 秒，token 消耗约 850-1200 tokens/张。

🔑 生产级多模态 prompt 的迭代路径：朴素→结构化→思维链→预处理，每轮优化可带来 10-15% 的准确率提升。最关键的是引入自验证逻辑。

视觉 token 成本通用公式 Cost_image = N_tiles × T_per_tile × P_input

⚠️ 风险与陷阱：多模态模型的「视觉幻觉」 风险~5 分钟

「看到」不等于「看对」——多模态模型中潜藏着比纯文本 LLM 更隐蔽的风险。

多模态模型继承了纯文本 LLM 的所有风险（幻觉、偏见、有害输出），同时引入了视觉模态特有的新风险维度：

第一类：视觉幻觉。模型可能「看到」图像中并不存在的内容。常见模式包括：(1) 物体虚构——在没有人的照片中描述人物；(2) 文本臆造——在模糊文字区域创造不存在的内容；(3) 关系幻觉——正确识别了两个物体但错误描述它们的空间关系。研究表明，当前最佳 VLM 在标准视觉 QA 上的幻觉率为 12-18%。

第二类：对抗性图像攻击。攻击者可以向图片中注入人眼不可见的扰动（adversarial perturbations），使模型产生完全错误的输出。更令人担忧的是视觉 prompt 注入——在图片中嵌入隐藏文本指令（如白色字体写在白色背景上），模型可能读取并执行这些隐藏指令，绕过文本层的安全防护。

第三类：空间推理失败。多模态模型在处理需要精确空间关系的任务时表现不稳定。例如：「图中有 5 个杯子排成一行，左数第三个是什么颜色？」模型可能正确识别了 5 个杯子，但左右方向判断错误。这种失败在涉及方向性介词（左/右、上/下、前/后）或计数+定位组合时尤为常见。

第四类：隐私泄露。用户上传的图片可能包含元数据（GPS 坐标、拍摄时间、设备信息），而这些数据在模型处理过程中可能通过 side-channel 泄露。一张看似寻常的街景照可能暴露用户的精确位置。

基准测试的局限性。虽然这些基准提供了有价值的比较框架，但存在几个重要局限：（1）分布偏移——基准图像多为高质量、良好光照的图片，与真实世界用户上传的模糊、倾斜、遮挡图片有显著差距；（2）语言偏差——大多基准以英文为主，中文场景的代表性不足（MMBench 有中文版本是一个进步）；（3）任务局限性——多选题形式无法评估模型在开放式视觉推理中的表现，而这恰恰是多模态提示工程最关注的场景；（4）数据污染——部分基准的测试图片可能已被包含在模型的训练数据中。

有效提示质量的代理评估公式 Prompt_Score = α · Task_Accuracy + β · Token_Efficiency + γ · Robustness

  α + β + γ = 1（典型取值：α=0.5, β=0.2, γ=0.3）
  Task_Accuracy = 在目标任务上的准确率
  Token_Efficiency = 1 - (实际token/预算token)
  Robustness = 在不同图像质量下的性能方差

第一阶段：基础入门（2-3 周）。目标：能熟练调用 GPT-4V/Claude Vision API 完成常见任务。核心内容：理解视觉 token 概念（1-2 天）；熟悉 OpenAI Vision API 和 Anthropic Messages API 的图像提交方式（2-3 天）；掌握 OCR、VQA、图像描述三大基础任务的 prompt 模板（1 周）；实践文档提取和 UI 分析两个完整场景（1 周）。推荐资源：OpenAI Vision Guide、Anthropic Vision Cookbook、LLaVA Demo。

❌ 常见误区：多模态提示的迷思与真相 误区~5 分钟

「把文本 prompt 技巧照搬到图像就行」「分辨率越高越好」——这些直觉可能是错的。

误区一：「文本 prompt 技巧可以直接迁移到多模态场景。」这是最常见也最危险的误解。虽然角色设定、few-shot 示例和输出格式控制在多模态中同样有效，但多模态 prompt 引入了文本场景中不存在的挑战：视觉定位问题——你无法用文字精确描述图像中的某个像素区域；视觉上下文污染——与文本上下文不同，图像中的无关元素可能分散模型的注意力。实际上，多模态 prompt 需要一套独立的技巧体系，包括空间引用、视觉 chain-of-thought、区域锚定等。

误区二：「图像分辨率越高，模型表现越好。」令人意外的是，高分辨率并不总是有益的。研究表明，对于某些场景级任务（如夜景分类、情感识别），中低分辨率反而优于高分辨率——因为高分辨率引入了更多噪声细节。而对于 OCR 和精细物体识别，分辨率确实至关重要。这引出一个核心原则：分辨率应当匹配任务需求，而非一味追求最高。

误区三：「多模态模型『理解』图像的方式和人类相似。」这是一个根本性的误解。人类视觉是一个主动的、注意力驱动的、具有三维空间感知的过程。而 VLM 通过分 patch、向量化和注意力权重来「感知」图像——它是一个被动的、基于二维 patch 统计的过程，对遮挡、光照变化和视角变换的鲁棒性远不如人类视觉。理解这一差异有助于设计更有效的 prompt（例如，通过显式描述光照条件和视角来弥补模型的不足）。

误区四：「空间推理不需要专门的 prompt 技巧。」实际上，空间推理是多模态模型最薄弱的环节之一。如果你的 prompt 涉及「左数第三个」、「第 5 行第 2 列」、「上方偏右」等空间描述，模型有 15-25% 的概率出错。有效的解决方案包括：(1) 使用网格叠加法——让模型先在图像上想象一个网格，再定位；(2) 使用逐区域分析法——先将图像分割描述，再进行空间关系推理。

误区五：「开源 VLM 的质量远不及商业 API。」在 2023 年这也许是事实，但到 2025 年，顶级开源模型（Qwen2-VL-72B、InternVL2-76B）在多个基准上已接近或持平 GPT-4V。更重要的是，开源模型在某些特定领域（如中文 OCR）和特定部署场景（边缘设备、数据隐私要求）中具有不可替代的优势。

🔑 多模态提示工程的最大陷阱是「文本迁移主义」——把纯文本 prompt 的思维模式不加改造地应用于视觉场景。放下旧的直觉，建立新的多模态思维框架。

🔮 未来展望：多模态提示的下一站 展望~5 分钟

实时视觉对话、3D 场景理解、具身智能——多模态提示工程的未来比想象中更近。

站在 2025-2026 年的时间节点，多模态提示工程正站在几个重大技术突破的交叉口：

趋势一：实时视频提示与流式视觉理解。当前的视频理解大多基于离线帧序列，但实时流式视觉理解正在成为现实。GPT-4o 和 Gemini 2.0 已支持摄像头实时输入，模型能在视频流中持续感知、跟踪和推理。prompt 设计的新范式：从一次性指令转变为持续性的「视觉监控指令」——例如「持续观察此监控画面，当有人进入红色区域时立即报告」。这要求 prompt 工程师定义触发条件、报告频率和优先级规则。

趋势二：3D 场景理解与空间推理。从 2D 图像走向 3D 理解是下一个大跳跃。NeRF 和高斯 Splatting 技术与 VLM 的结合使得从多视角 2D 图像推理 3D 空间关系成为可能。未来的 prompt 可能是：「请分析这组 360° 产品照片，生成产品的 3D 结构描述和尺寸估算。」

趋势三：具身智能提示。当 VLM 被部署到机器人、AR 眼镜和智能座舱中，prompt 需要协调「感知-决策-行动」闭环。这类 prompt 的关注点从「描述你看到了什么」转变为「基于你的视觉观察，决定下一步行动」。prompt 设计需要包含行动空间定义、安全约束和实时反馈循环。

趋势四：多模态 Agent 与工具调用。模型不仅能看图，还能基于视觉信息主动调用工具——看到表格就调用 Python 做数据分析，看到 UI 界面就自动操作。这让多模态 prompt 从「问答」进化为「任务执行规范」，需要定义工具接口、错误处理策略和完成标准。

趋势五：端侧多模态推理。随着模型压缩和量化技术的进步（MiniCPM-V 2.8B 已能在手机上运行），边缘设备上的多模态 prompt 工程将成为一个新领域，需要平衡精度、延迟和功耗。
